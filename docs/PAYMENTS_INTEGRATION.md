# HotelPro — Ethiopian Payment Gateways Integration Specification

This document details the production integration specifications and remaining requirements for automated mobile money payment processing in Ethiopia (Telebirr and CBE Birr), alongside the manual recording workflow active during the initial pilot.

---

## 1. Pilot Payment Architecture (Currently Operational)

During the limited property pilot, payments are recorded via HotelPro's native manual settlement workflow:
1. When a guest or diner pays via **Telebirr** or **CBE Birr**, the customer transfers funds directly to the property's merchant till number or shortcode.
2. The customer shows the confirmation SMS or transaction screen to the cashier / waiter.
3. The cashier opens the payment modal in the Web or Mobile terminal:
   - Selects method: `TELEBIRR` or `CBE_BIRR`.
   - Enters the unique transaction reference code (e.g., `CL89X20489` or `FT26289012`).
   - Confirms the exact amount in ETB.
4. The system:
   - Verifies the user has an active cashier shift.
   - Atomically updates the reservation folio or restaurant order balance.
   - Records the payment in `Payment` with `processedByUserId` and timestamp.
   - Updates the cashier shift reconciliation records.

> [!IMPORTANT]
> **Zero Simulation Policy**: HotelPro strictly avoids mock or simulated "auto-success" for payment gateways. Automated gateways are only enabled with verified credentials and signed cryptographic webhook verification.

## 2. Automated Telebirr Direct Integration Requirements

To enable direct automated customer checkouts (H5 Web Checkout and QR push) via Telebirr (Ethio Telecom), the following credentials and components must be provisioned:

### 2.1 Required Merchant Credentials from Ethio Telecom
- **`TELEBIRR_APP_ID`**: Unique Application ID registered with Ethio Telecom.
- **`TELEBIRR_APP_KEY`**: Application authentication key.
- **`TELEBIRR_SHORT_CODE`**: Merchant till/shortcode (5–6 digits).
- **`TELEBIRR_PRIVATE_KEY`**: 2048-bit RSA Private Key generated by HotelPro (PEM format), used to sign payment request payloads with `SHA256withRSA`.
- **`TELEBIRR_PUBLIC_KEY`**: Telebirr's official RSA Public Key, used to verify incoming webhook signatures and decrypt callback data.
- **`TELEBIRR_API_URL`**: Gateway endpoint (Production: `https://app.ethiomobilemoney.et:2121/ammapi/payment/service-open/v1/h5/order`).

### 2.2 Telebirr Architecture & Message Flow
```
[Customer Mobile / Web] 
      │
      │ 1. Request Checkout
      ▼
[HotelPro API] ── 2. Create Signed Order Payload ──► [Telebirr H5 Gateway]
      │                                                     │
      │ 3. Redirect / Render toPayUrl                       │ 4. Customer Authorizes PIN
      ▼                                                     ▼
[Customer Screen]                                  [Ethio Telecom Core]
                                                            │
                                                            │ 5. Asynchronous Webhook
                                                            ▼
[HotelPro API Webhook Listener] ◄───────────────────────────┘
      │
      │ 6. Verify RSA Signature & Decrypt
      │ 7. Atomically Update Folio / Order & Link Cashier Shift
      ▼
[PostgreSQL Database]
```

### 2.3 Remaining Implementation Steps for Telebirr
1. Obtain signed merchant agreement and test credentials from Ethio Telecom Business Division.
2. Implement cryptographic helper in `apps/api/src/modules/financials/telebirr.service.ts`:
   - RSA SHA256 string signing.
   - AES-128-CBC encryption of order parameters using Telebirr public key.
3. Implement `/api/v1/financials/webhooks/telebirr`:
   - Validate HTTP headers and decrypted signature.
   - Check payment amount matches expected order or folio balance.
   - Ensure idempotency using Telebirr `outTradeNo`.

## 3. Automated Commercial Bank of Ethiopia (CBE Birr) Integration Requirements

To enable direct bank push debits and QR payments via CBE Birr:

### 3.1 Required Merchant Credentials from CBE
- **`CBE_BIRR_MERCHANT_ID`**: CBE assigned Merchant ID.
- **`CBE_BIRR_API_KEY`**: Secret API key for REST authentication.
- **`CBE_BIRR_WEBHOOK_SECRET`**: HMAC shared secret for webhook validation.
- **`CBE_BIRR_API_URL`**: CBE Birr API gateway endpoint.

### 3.2 CBE Birr USSD / QR Flow
1. Guest requests to pay with CBE Birr.
2. Front desk initiates prompt:
   - Request sent to CBE Birr API with guest phone number and amount.
   - Guest receives USSD flash prompt (`*847#`) to confirm payment with CBE Birr PIN.
3. CBE Birr notifies HotelPro webhook with settlement status and CBE transaction reference.
4. HotelPro marks folio as paid and issues receipt.

### 3.3 Remaining Implementation Steps for CBE Birr
1. Complete CBE Merchant Onboarding Agreement.
2. Implement CBE Birr API client in `apps/api/src/modules/financials/cbe.service.ts`.
3. Implement webhook endpoint `/api/v1/financials/webhooks/cbe` with HMAC-SHA256 signature verification.

## 4. Security & Compliance Requirements for Payments

- **No Card / PIN Storage**: HotelPro never collects, handles, or stores customer PINs, CVVs, or bank credentials.
- **TLS 1.3**: All payment callbacks must be served over secure HTTPS.
- **Audit Trails**: All payments record IP address, cashier ID, timestamp, and transaction reference in the immutable `AuditLog` table.
- **Idempotency**: Webhook endpoints must reject duplicate callbacks with identical transaction reference codes.
